## ⚠️ 2026-09-22：采集页流程大改，先看这一段

**四项改动 + 一项落盘**，落在采集页上：

1. **进发货/退货栏，相机自动开**、并播报「发货模式开启」/「退货模式开启」
2. **底部合成一个按钮**：绿【开始】↔ 红【结束】。原来的【开始工作】【结束工作】
   「停止当前录制」**都不存在了**
3. **连续扫改成换段式**：扫到**新面单** → 上一段立刻入库、这一件紧接着开录
4. **面单进框自动对焦 + 放大 2 秒**，然后回原倍率
5. **发货 / 退货写进 `labels.jsonl`**（标签表）

**新流程一句话：**

```
进发货栏 → 相机自己开、播报「发货模式开启」   ← 这时还不录
面单进框 → 自动放大两秒 → 识别到 → 开始录
扫到别的面单 → 上一段入库，这一件紧接着开录    ← 只有连续扫这样
点底部红【结束】→ 收尾，**相机不关**
```

**下面 1.1 ~ 1.7 里凡是写【开始工作】的，一律读作「进【发货】栏」。
写【结束工作】的，一律读作「点底部红【结束】」。** 详细的五条验收见
清单里的 **§1.15** —— 那份写全了，这份只给操作。

## 先跑这三步，不对就停

> **界面是底部四个栏**：**备份 / 发货 / 退货 / 设置**。
> 发货与退货**共用同一个采集页**（只是各播各的模式、各写各的标签）。
> 采集页是**全屏取景**，验收工具收在底部抽屉里（点底部把它拉出来）。
>
> 下面每条写的「前置」都在**设置页**调，调完切回发货栏操作。
> 档位是**开录时**定下来的，中途改要重新开始工作才生效。

**这条不过，后面每条都无从谈起。**

| # | 操作 | 通过判据 |
|---|---|---|
| 0.1 | 打开 App | 状态栏不是「初始化失败」 |
| 0.2 | 点【**发货**】栏 | **画面出现**（不是黑屏/白屏），且听到「发货模式开启」 |
| 0.3 | 看画面中间 | **有一个框**：框外偏暗，框上有绿色四角 |

**同时**：状态栏写「**把面单放进取景框**」，**不是**「录制中」。

> 黑屏 → 预览没挂上会话
> 没有框 → 覆盖层没画出来
> 已经是「录制中」→ 退回"点按钮就开录"了
> 状态栏写「开相机失败：…notImplemented」→ **你在安卓上**（安卓那条通道本来就是断的，见清单 §3）

## 1.1 连续录 30 分钟不断

| | |
|---|---|
| **前置** | 模式：连续扫 · 静止档位：**关闭** |
| **操作** | 进【发货】栏 → 扫一张面单开录 → 手机架着录 30 分钟 |

> 判据 3 很关键：30 分钟只出 1 条，说明轮转没发生或丢段了。

## 1.4 ★ 静止封顶修正

**这是最容易写错的一条。**

| | |
|---|---|
| **前置** | 模式：连续扫 · 静止档位：**2 分钟** · 时长兜底：**关闭** |
| **操作** | **先别碰手机，让它静止放着 10 分钟以上** → 然后进【发货】栏 → 扫面单开录 → 放下手机 |
| **判据 1** | **不得立刻停止** ← 这条是核心 |
| **判据 2** | 事件里出现「👁 画面静止 —— 静止计时从现在起算」 |
| **判据 3** | 从**那一刻**起 2 分钟后才停 |

> ### ⚠️ 别用「开录后多久停的」来判断
>
> **静止计时从「画面真的静下来」起算，不是从开录起算。**
>
> 你扫码时要拿着手机，画面是动的 —— 静止计时会被重置。
> 所以「开录后 4 分钟才停」= **扫码折腾了 2 分钟 + 静止 2 分钟**，
> 这是**正确**的（封顶失效的话会一开录就停）。
>
> 看那行 👁 日志最准：**它出现之后再等 2 分钟才停 = 通过。**

## 1.5 错码保护

| | |
|---|---|
| **前置** | 模式：**同码停** · 静止档位：关闭 · 时长兜底：关闭 |
| **操作 A** | 进【发货】栏 → 扫面单 **A** 开录（扫完把 A 拿开）→ 扫面单 **B** |
| **判据 A** | **不停止** 且 事件里出现「🔊 **面单不同**」 |
| **操作 B** | 再扫回 **A** |
| **判据 B** | **停止**，事件里出现「停录 · **同码复扫**」 |

> ⚠️ **前置必须是「同码停」**。2026-09-22 起**连续扫不再有错码保护** ——
> 连续扫下扫到 B 就是「换件」，会收掉这一段、为 B 开新段。别拿连续扫验这一条。

> 没有两张不同面单时：用界面上的「**当作扫到了这个单号**」按钮，
> 改单号文本框的内容再点，效果一样。

## 1.15 ★ 新流程四项（2026-09-22）

> 这是这一批的主菜。完整的判据在 [`真机验收清单.md`](真机验收清单.md) §1.15，
> 这里只给操作口径。

### ① 进栏自动开相机 + 播报

| | |
|---|---|
| **操作** | 从备份栏点【发货】；再点【退货】；再点一次已经选中的那一栏 |
| **判据** | ①相机自己开、播报「发货模式开启」 ②切退货**只重播、相机不闪** ③**重复点当前栏不重播** |
| **判据** | 冷启动停在**备份栏**时相机**不开**；从发货切到设置再切回来 → **重新播报** |

### ② 底部只有一个按钮

| | |
|---|---|
| **操作** | 看底部中间 |
| **判据 1** | 只有**一个**按钮：绿【开始】 → 按下变红【结束】 |
| **判据 2** | **没有**「停止当前录制（相机继续开着）」—— 删了，**别再找它** |
| **判据 3** | 点【结束】后录像收尾了，**但相机还开着**（= 回到刚进栏那个状态） |

### ③ ★ 连续扫换段式（最需要认真验的一条）

| | |
|---|---|
| **前置** | 模式：**连续扫** |
| **操作** | 按【开始】→ 扫 **A** → 拿开 → 放 **B** → 拿开 → 放 **C** → 按【结束】 |
| **判据 1** | 换件时 **A 立刻入库、B 紧接着开录**（不该停下来等人点一下） |
| **判据 2** | 录像记录里 **A、B、C 各一条**，不是一条长录像 |
| **判据 3** | 换段时**不播**「面单不同」 |
| **判据 4** | ⚠️ **另两个模式不受影响** —— 回 §1.5 用**同码停**再跑一遍，必须照旧只提示不换段 |

> ⚠️ **两个已知代价，别当 bug 记**：
> 换段有 **1~3 秒空档**（丢的是打点对齐，**不是画面** —— 原件连续，一帧不少）；
> 连续扫下画面里**别的条码会当场切断**当前录制（邻件、货架标签），
> 代价是一件包裹被劈成两条会话。**这是决策。**

### ④ 自动对焦 + 放大两秒

| | |
|---|---|
| **操作** | 面单进框 → 看画面 |
| **判据 1** | 放大到 **2 倍**、字变清楚，约 **2 秒后**回原倍率 |
| **判据 2** | 自己先把表盘拖到 **3 倍**，再让面单进框 → **不先缩回去** |
| **判据 3** | 自动放大那 2 秒里**拖表盘** → 立刻生效，**2 秒后不该跳回去** |
| **判据 4** | 手输兜底输单号 **不触发放大** |

> ⚠️ 表盘显示的是**你自己设的倍率**，不是那 2 秒里的瞬时值 —— **有意的**。

### ⑤ ★ 发货 / 退货落盘

| | |
|---|---|
| **操作** | 发货栏录一段、退货栏录一段，然后去「文件」App 里 App 自己的目录找 `labels.jsonl`（跟 `index.jsonl` 同一层） |
| **判据 1** | 每录一段多**一行**；发货是 `"Value":"outbound"`，退货是 `"Value":"return"` |
| **判据 2** | 键名是 **PascalCase**：`EvidenceId` / `Key` / `Value` / `UpdatedAt`，`"Key":"business-type"` —— **不是笔误**（两端已对齐的格式） |
| **判据 3** | ★ **把这份 `labels.jsonl` 拷到电脑端，看它认不认** —— 这是唯一能证明两端写的是同一份东西的办法 |
